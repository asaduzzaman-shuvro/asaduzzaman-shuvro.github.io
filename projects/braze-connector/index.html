Professional

Braze engagement connector

A Java service that connects NHST's client systems to Braze for customer-engagement messaging — 100K+ events a day.

Role
Staff Engineer & Team Lead
Team
5 engineers (iOS + backend)
Tech
Java, Spring Boot 3, Braze, REST APIs
  • ▸ Handles 100K+ customer-engagement events per day.
  • ▸ Bridges client services and Braze, powering push, email and in-app messaging.
  • ▸ Built and run while leading the team and still shipping mobile features.

Context

The problem. Push notifications, emails and in-app messages only work if Braze knows what readers are doing. NHST’s client services held that data, but nothing reliably moved it to Braze.

My role

As Staff Software Engineer I built and maintain the connector, while leading the combined iOS and backend team (5 engineers) and setting backend standards for Java, Spring and RabbitMQ.

Technical highlights

  • Built for volume. The connector handles more than 100K events a day.
  • Standards first. It’s built on the Java and Spring standards I set for the team’s backend work, alongside RabbitMQ-based services.
  • Mobile meets backend. The same team owns the apps, so I kept contributing mobile features while building the connector.

Outcome

A dependable pipeline at 100K+ events a day that powers NHST’s customer-engagement messaging — and a backend codebase with clear standards the team can build on.
